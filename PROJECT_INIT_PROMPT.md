# Project Initialization Prompt — edu-operations-research

Ты работаешь в проекте `edu-operations-research`.

## Режим работы (обязательно)

1. Для трекинга задач используй **Beads (bd)** как единственный источник задач.
2. Для навигации/рефакторинга кода используй **Serena MCP**.
3. Префикс issue в этом проекте: **`eor-`** (аббревиатура от *edu operations research*).

## Старт каждой сессии

```bash
bd prime
bd ready
```

Если готовых задач нет — создай новую через Beads:

```bash
bd create "<title>" --type task --priority 2 --description "<context>" --prefix eor-
```

## Сначала анализ проекта, потом новая лабораторная

Перед созданием новой лабораторной работы обязательно проанализируй текущий проект:

1. Через **Serena MCP** найди и изучи существующие лабораторные (`01-lab-essentials/*`) и их структуру.
2. Зафиксируй шаблон: стиль формулировок, глубину теории, формат заданий, требования к проверке результатов.
3. Проверь переиспользуемые компоненты/данные/ноутбуки, чтобы не дублировать уже сделанное.
4. Сформируй краткий план новой лабораторной: цель, входные данные, шаги, критерии проверки.

Нельзя генерировать новую лабораторную «с нуля в вакууме» без этого анализа.

## Правила по issue

- Любая новая задача/баг/улучшение фиксируется в Beads.
- Все ID задач должны иметь префикс `eor-`.
- Перед коммитом проверь, что работа привязана к корректному issue ID.

## Правильное использование MCP-серверов (для новых лабораторных)

- **Serena MCP** — основной сервер для анализа проекта:
  - находи релевантные файлы и модули;
  - восстанавливай логику существующих лабораторных;
  - проверяй, куда и как интегрировать новую работу без ломки структуры.
- **Beads MCP** (или `bd` CLI, если MCP временно недоступен):
  - создай задачу на новую лабораторную с префиксом `eor-`;
  - веди работу в рамках issue до полного закрытия.
- **Доп. MCP по необходимости** (например, документация библиотек):
  - используй только после проектного анализа;
  - любые внешние справки применяй так, чтобы не нарушать внутренний стиль и методику курса.

Минимальный рабочий контур для новой лабораторной:
1. Проанализировать проект через Serena.
2. Создать issue (`eor-...`) в Beads.
3. Согласовать план лабораторной (цель, шаги, критерии проверки).
4. Реализовать материалы и проверить целостность проекта.
5. Закрыть issue.

## Статус Codex MCP

**Beads MCP server подключён** в `~/.codex/config.toml`.

Используемый блок конфигурации:

```toml
[mcp_servers.beads]
command = "/home/sorcerer/.local/bin/beads-mcp"
args = []
startup_timeout_sec = 60.0
tool_timeout_sec = 180.0
```

Если beads MCP временно недоступен, операции с задачами выполняй через CLI `bd`.
