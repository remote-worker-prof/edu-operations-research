# ЛР-04: Задача о назначениях

## 1) Зачем нужна именно эта лабораторная

После ЛР-01 мы научились собирать базовую LP-постановку и решать её через `linprog`.

После ЛР-02 мы освоили матричную логику потоковой модели и аккуратную работу с ограничениями.

После ЛР-03 мы увидели, как читать решение глубже через интерпретацию ограничений и параметров.

**ЛР-04 добавляет практичный и компактный класс задач:**

> есть исполнители и задачи, и нужно построить взаимно-однозначное назначение с минимальными затратами.

Это один из самых частых операционных кейсов в расписаниях, логистике, ремонте и оперативном планировании.

---

## 2) Прикладной контекст

Типичные ситуации:

1. аварийные бригады распределяются по районам;
2. преподаватели назначаются на учебные группы;
3. ремонтные команды назначаются на конкретные единицы техники;
4. экипажи распределяются по вылетам.

Во всех этих случаях структура одинаковая:

- есть квадратная таблица затрат;
- строка — исполнитель;
- столбец — задача;
- значение в ячейке — цена назначения (время, пробег, риск, штраф и т.д.).

---

## 3) Математическая постановка

Пусть:

- $c_{ij}$ — затраты, если исполнителя $i$ назначить на задачу $j$;
- $x_{ij} \in \{0,1\}$ — бинарная переменная назначения.

Тогда задача:

$$
\min Z = \sum_{i=1}^{n}\sum_{j=1}^{n} c_{ij} x_{ij}
$$

при ограничениях:

$$
\sum_{j=1}^{n} x_{ij} = 1, \quad i = 1,\ldots,n
$$

$$
\sum_{i=1}^{n} x_{ij} = 1, \quad j = 1,\ldots,n
$$

$$
x_{ij} \in \{0,1\}.
$$

Смысл ограничений простой:

- каждый исполнитель получает ровно одну задачу;
- каждая задача получает ровно одного исполнителя.

---

## 4) Связь с транспортной задачей

Задача о назначениях — это частный случай транспортной модели:

- у каждого поставщика запас равен 1;
- у каждого потребителя спрос равен 1;
- потоки становятся бинарными назначениями.

Поэтому ЛР-04 естественно следует после транспортной темы: форма похожа, но интерпретация ещё проще.

---

## 5) Практическое решение через `linear_sum_assignment`

В SciPy есть готовая функция:

```python
from scipy.optimize import linear_sum_assignment
```

Она возвращает пары индексов `(row_ind, col_ind)` — оптимальное назначение строк на столбцы.

Суммарные затраты считаются так:

```python
total_cost = cost_matrix[row_ind, col_ind].sum()
```

Для учебной лабораторной это самый прямой и наглядный способ получить решение и сразу перейти к интерпретации.

---

## 6) Короткая проверка через LP-форму

Чтобы связать тему с уже изученным `linprog`, используйте релаксационную постановку:

- разверните матрицу в вектор переменных;
- соберите `A_eq`, `b_eq` для строк и столбцов;
- задайте границы `0 <= x <= 1`.

Для модели назначений матрица ограничений тотально унимодулярна, поэтому оптимум LP-версии даёт целочисленное решение в вершине.

Практический вывод: сравнение результатов `linear_sum_assignment` и `linprog` даёт независимую проверку корректности.

---

## 7) Как интерпретировать решение

Недостаточно записать только оптимальную сумму. В отчёте обязательно проговорите:

1. кто на какую задачу назначен;
2. почему такая комбинация логична предметно;
3. какие назначения оказались «дорогими» и где узкие места;
4. как меняется план при точечном изменении одной-двух стоимостей.

Именно прикладная интерпретация показывает, что модель действительно понята.

---

## 8) Что должно быть в отчёте

1. Таблица исполнителей, задач и матрица затрат.
2. Формулировка переменных $x_{ij}$ и ограничений «один к одному».
3. Решение через `linear_sum_assignment`.
4. Таблица итоговых назначений `assignment_df` и суммарный критерий `total_cost`.
5. Проверки ограничений «один к одному» через `assert`.
6. LP-проверка через `linprog` и сравнение результатов.
7. Один мини-сценарий изменения стоимости и вывод по изменению решения.
8. Краткий управленческий вывод по кейсу.

## 9) Единый учебный маршрут ЛР-04

| Этап | Что делаем | Какой результат фиксируем |
| --- | --- | --- |
| 1. Контекст | Формулируем задачу и критерий | Понимание предметной цели кейса |
| 2. Данные | Записываем матрицу затрат | Корректная таблица входных данных |
| 3. Мини-пример 3x3 | Проверяем логику назначения вручную | Черновая проверка интуиции |
| 4. Решение | Решаем через `linear_sum_assignment` | `row_ind`, `col_ind`, `assignment_df`, `total_cost` |
| 5. Проверка ограничений | Проверяем «один к одному» через `assert` | Подтверждение корректности назначения |
| 6. LP-проверка | Решаем эквивалентную LP-форму через `linprog` | Таблица сравнения двух методов |
| 7. Мини-сценарий | Меняем один параметр и пересчитываем | Понимание чувствительности результата |
| 8. Интерпретация | Пишем итоговый вывод | Обоснованный ответ «почему именно такое назначение» |

Тот же порядок должен сохраняться и в ноутбуке для самостоятельной работы, и в разобранном примере.

---

## 10) Типичные ошибки

1. Путать задачу о назначениях с транспортной задачей, где допустимы дробные объёмы.
2. Ограничиваться только `total_cost` без таблицы соответствий.
3. Неправильно интерпретировать пары индексов `row_ind`, `col_ind`.
4. Забывать проверять размерность матрицы затрат.
5. Делать вывод по сценарию, не пересчитав модель после изменения стоимости.
